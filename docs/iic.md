# I²C（IIC）通信学习笔记

## 1. 先复习：什么是半双工？

- **全双工**：双方能够**同时**向对方发送数据，例如电话交谈。
- **半双工**：双方都能发送和接收，但**同一时刻只有一个方向在发送有效数据**，例如轮流讲话的对讲机。

区别不在于哪个更快，而在于**能否同时双向传输**。

SPI 常见四线模式可以全双工；I²C 的典型数据传输是半双工，因为收发数据共用同一根 SDA 线。

## 2. I²C 是什么？

I²C（Inter-Integrated Circuit，也常写作 IIC）是一种芯片之间使用的**同步串行通信总线**。

“总线”可以理解为：**多颗芯片共同使用一组信号线**。例如 C 板的 STM32 可以使用 I²C 与磁力计等器件通信。

I²C 常用两根信号线：

```text
                 ┌── 传感器 A
STM32 ── SCL ────┼── 传感器 B
      ── SDA ────┴── 传感器 C
```

- **SCL**：时钟线，提供传输节拍。
- **SDA**：数据线，发送和接收都通过它完成。

注意：图中只画了通信信号线，实际电路还需要电源、地线和适当的上拉电阻。

## 3. 只有两根线，STM32 怎样知道在和谁通信？

SPI 一般靠不同 CS 引脚选设备；**I²C 靠设备地址选设备**。

可以把它理解为：同一间教室有很多同学，老师不需要为每个人准备一根独立的“点名线”，而是直接说出名字。

I²C 中，STM32 发起通信时先发送目标设备的**总线地址**（常见的是 7 位地址）。只有地址匹配的设备才响应。

注意不要混淆两个地址：

- **设备地址**：找到哪一颗芯片。
- **寄存器地址**：找到这颗芯片内部哪一份数据。

例如“找某个传感器 → 读它的温度寄存器”，就需要先选设备，再指定寄存器。

## 4. STM32 怎样用 I²C 读取寄存器？

假设 STM32 要读取某个传感器的测量值，典型过程是：

1. **START（开始）**：STM32 通知总线“我要开始通信”。
2. **设备地址 + 写方向**：找到目标设备，告诉它接下来要先接收信息。
3. **寄存器地址**：告诉设备准备读取哪一个寄存器。
4. **Repeated START（重复开始）**：不释放总线，切换到读取阶段。
5. **设备地址 + 读方向**：告诉设备“现在请把数据发给我”。
6. **接收数据**：设备通过 SDA 逐位发送，STM32 根据 SCL 读取。
7. **NACK + STOP（结束）**：主机在典型单字节读取的最后发送 NACK，表示不再继续读取，然后结束通信。

`START` 是 SCL 为高时 SDA 从高变低；`STOP` 是 SCL 为高时 SDA 从低变高。7 位设备地址与 1 位读写位在线上组成一个地址字节：`(address << 1) | R/W`。

```text
S | 地址+W | ACK | 寄存器 | ACK | Sr | 地址+R | ACK | 数据 | NACK | P
```

这只是一种常见的寄存器读取流程，不是所有 I²C 设备都采用完全相同的命令格式。

### 什么是 ACK / NACK？

I²C 每传完一个字节（8 位），通常还有第 9 个时钟用于**应答**：

- **ACK**：接收方把 SDA 拉低，表示确认收到。
- **NACK**：不拉低 SDA；可能是设备未响应，也可能是主机主动表示“最后一个字节收完了”。

所以 NACK **不一定代表通信出错**，要结合发生的位置判断。

## 5. 为什么 I²C 要用上拉电阻？

I²C 的 SDA、SCL 通常使用**开漏**方式：设备可以把线**拉低**，但不会主动把线**推高**。

那高电平从哪里来？答案是**上拉电阻**：当没有设备拉低时，它把信号线维持在高电平。

这样多个设备共享同一根线时，能避免一个设备强推高电平、另一个设备强拉低电平而直接冲突。

直观记忆：**谁需要发低电平，就把线拉低；都不拉低时，电阻把线拉高。**

## 6. I²C 通信有什么特点？

**优点：**

- 只需要 SCL、SDA 两根通信信号线。
- 多个设备可以共享总线，通过设备地址区分。
- 非常适合连接温度计、磁力计、EEPROM 等低到中等速率外设。

**局限：**

- 数据收发共用 SDA，典型工作方式是半双工。
- 通常比常见高速 SPI 慢，常用速率有 100 kHz、400 kHz。
- 依赖正确的上拉电阻和布线；地址错误、总线被拉低都可能导致通信失败。

## 7. CubeMX 里常见的 I²C 参数

| 参数 | 是什么意思？ |
| --- | --- |
| I2C Speed | SCL 时钟速度，例如 100 kHz |
| 7-bit Addressing | 使用常见的 7 位设备地址格式 |
| SCL / SDA | 时钟线和双向数据线 |
| Open Drain | 输出低电平靠主动拉低；高电平靠上拉电阻 |

写 STM32F4 HAL 程序时还要注意：`DevAddress` 参数传入 **7 位地址左移一位**后的值，读写位由 HAL 处理。

## 8. STM32 HAL 最小用法

- `HAL_I2C_Master_Transmit()` / `HAL_I2C_Master_Receive()`：传输原始字节流，应用自己组织命令。
- `HAL_I2C_Mem_Read()` / `HAL_I2C_Mem_Write()`：完成常见的内部寄存器读写。

```c
uint8_t value;
uint16_t dev = (uint16_t)(sensor_addr_7bit << 1);
HAL_StatusTypeDef status = HAL_I2C_Mem_Read(
    &hi2c2, dev, reg, I2C_MEMADD_SIZE_8BIT, &value, 1, 10);
```

这里 `dev` 是设备地址，`reg` 是设备内部寄存器地址，`&value` 是数据缓冲区。应检查 `status == HAL_OK` 后再使用数据。

## 9. UART、SPI、I²C、CAN 对比

| 接口 | 同步方式 | 典型方向能力 | 信号线 | 寻址 | 特点与常见应用 |
| --- | --- | --- | --- | --- | --- |
| UART | 异步 | 全双工 | TX、RX | 无 | 点对点、调试串口 |
| SPI | 同步 | 协议可全双工，也可半双工/单向 | SCK、MOSI、MISO、CS | 片选 | 快；IMU、Flash |
| I²C | 同步 | 典型半双工 | SCL、SDA | 设备地址 | 两线多设备；传感器、EEPROM |
| CAN | 异步但进行位同步 | 典型半双工总线 | CANH、CANL | 报文 ID | 仲裁、差分抗干扰；车载网络 |

**最重要的理解：** I²C 用 **SCL 提供节拍、SDA 双向传数据、设备地址选芯片、ACK 确认接收**。

## 10. 常见错误与定位

- **设备无应答**：核对供电、接地、地址选择脚，以及 7 位地址是否正确左移。
- **上拉错误**：空闲线不为高或上升沿过慢；用示波器检查 SDA/SCL，而不只看 HAL 返回值。
- **总线被拉低**：可能是从机掉电、事务中断或短路，应先定位拉低者，不要无限重试。
- **超时或 `HAL_BUSY`**：检查总线是否空闲、从机是否拉伸时钟、多个线程是否并发使用同一句柄。
- **寄存器读错**：确认寄存器地址长度、Repeated Start 要求和数据手册地址格式。
